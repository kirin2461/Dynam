## Part 1 — v1.5.3–1.6.0 feature review

### Zone A — v1.6.0 selective packet-level desync (WinDivert hostlist/ipset)

**Files**: `src/core/src/ncp_dpi.cpp`

| ID | Item | Status |
|----|------|--------|
| **R17-A01** | Hostlist/ipset state is loaded and gated, not a stub | ✅ Verified (source) |
| **R17-A02** | Empty/missing list → desync applies to ALL (documented fail-open) | ✅ By design |
| **R17-A03** | Suffix matching is loop-based longest-to-shortest | ✅ Verified |
| **R17-A04** | Minor: exclude-mode + include-file precedence | ⚠️ Observation |

- `ncp_dpi.cpp:237-241` holds `hostlist_`, `hostlist_active_`, `hostlist_exclude_mode_`, `ipset_`, `ipset_active_`. Config load at `:1556-1616` clears state first, then populates; an empty file explicitly logs "desync applies to ALL sites" and leaves `hostlist_active_=false` (`:1580-1581`). This matches the README contract.
- `hostlist_match()` (`:1623-1632`) lowercases/trims then walks label-by-label (`h.substr(dot+1)`), so `example.com` covers `www.example.com`. Correct suffix semantics.
- `ipset_match()` (`:1634-1640`) converts to host order once and tests `(h & mask) == net`. Correct CIDR containment.
- **R17-A04 (minor)**: at `:1562-1565`, when `hostlist_file` is empty but `hostlist_exclude_file` is set, the exclude file is adopted and `hostlist_exclude_mode_=true`. If an operator sets *both* an include file and an exclude file, only the include file is honored and the exclude file is silently ignored. Recommend logging when both are provided so the precedence is visible. Not a security issue.
- **Observation**: `init_windivert()` (`:1642+`) copies `WinDivert.dll`/`WinDivert64.sys` from hard-coded `C:\WinDivert-*` SDK paths into the exe dir when missing. Convenient, but copying a driver binary from a world-writable-by-default location is a mild supply-chain consideration; acceptable for a tool run as Administrator, worth a note in docs.

### Zone B — v1.5.5 system-proxy safety net

**Files**: `web/bypass_routes.py`, `web/server.py`

| ID | Item | Status |
|----|------|--------|
| **R17-B01** | System proxy restored on graceful stop | ✅ Verified |
| **R17-B02** | Stale proxy healed at startup | ✅ Verified |
| **R17-B03** | `restore_system_proxy` is idempotent | ✅ Verified (by comment + call sites) |

- `restore_system_proxy()` (`bypass_routes.py:140`), `heal_stale_system_proxy()` (`:200`, delegates to restore), and the stop path (`:180-197`) all exist and are wired. `server.py:1173` ("always stop the desync proxy and restore") and `:2370-2376` (startup heal) confirm both the stop and startup-heal halves of the v1.5.5 claim.
- The C++ engine only restores on **graceful** exit (comment `bypass_routes.py:71`); the Python supervisor is the crash/kill safety net via `atexit` + startup heal. This layering is sound, but it means a crash of *both* the engine and the Python supervisor (e.g. hard power loss) can still leave a stale proxy — healed on next launch. Correctly documented; no fix needed.

### Zone C — v1.5.4 DoH endpoint cascade + bounded timeouts

**Files**: `src/core/src/doh.cpp`, `src/core/src/ncp_self_test_monitor.cpp`

| ID | Item | Status |
|----|------|--------|
| **R17-C01** | Cascade iterates configured provider first, then all known endpoints | ✅ Verified |
| **R17-C02** | Bounded connect (1.5 s) + read (2 s) timeouts | ✅ Verified |
| **R17-C03** | Certificate pinning is fail-closed only when pins configured | ✅ Verified |
| **R17-C04** | Minor: cascade tries endpoints strictly sequentially | ⚠️ Observation |

- Cascade at `doh.cpp:728-753`: builds `urls` = configured provider + every other `DOH_SERVERS` entry, returns on first non-empty response, logs once when a fallback is used, throws "All DoH endpoints unreachable" if none answer (`:751-752`). Matches the "6 endpoints, never stuck on a dead one" claim.
- Bounded I/O: `tcp_connect_timeout()` (`:507-544`) does a non-blocking connect + `select` with the caller's timeout; call site `:619` uses 1500 ms connect and `:623` sets `SO_RCVTIMEO`. Comment `:617-618` documents the rationale. Good.
- Pinning (`:638-662`): only enforced when `enable_certificate_pinning` AND a non-empty pin set exists for the exact `server_url`; otherwise standard `SSL_VERIFY_PEER` path (`:169-170`) applies. Pin mismatch refuses the endpoint (`:660-662`). This is the fail-closed-when-configured behavior r16 established — still intact.
- **R17-C04 (minor/perf)**: the cascade is strictly sequential, so a run where the first few endpoints are null-routed pays `~1.5 s × N` before reaching a live one. Functionally correct (bounded), but a small happy-eyeballs-style parallel race of 2–3 endpoints would cut worst-case latency. Optional enhancement, not a defect.
- **Observation**: `doh.cpp:534` uses `select(fd + 1, …)`. On Windows the `nfds` argument is ignored and socket handles are not small ints, so this is harmless there; on POSIX `fd+1` is correct. No change needed, noted for completeness.
